Lab 7: CPU Scheduling Algorithms and Fairness

สรุปความเข้าใจ

จากการทดลอง cpu_scheduler.py ฉันได้เปรียบเทียบการจัดตาราง CPU
ระหว่าง FCFS และ Round Robin โดยมี Process P1 ใช้ CPU 10 units,
P2 ใช้ 2 units และ P3 ใช้ 3 units

เมื่อใช้ FCFS ระบบให้ P1 ทำงานจนเสร็จก่อน ทำให้ P2 ต้องรอ 10 units
และ P3 ต้องรอ 12 units แม้ว่า P2 และ P3 จะเป็นงานที่ใช้เวลาสั้นกว่า
ผลที่ได้คือ Average Waiting Time เท่ากับ 7.33 และ
Average Turnaround Time เท่ากับ 12.33

จากผลนี้ ฉันเข้าใจ Convoy Effect ว่าเกิดขึ้นเมื่อ Process ที่ใช้เวลา
ประมวลผลนานอยู่ด้านหน้าของคิว ทำให้ Process ขนาดเล็กที่อยู่ด้านหลัง
ต้องรอเป็นเวลานานทั้งที่สามารถทำงานเสร็จได้อย่างรวดเร็ว

เมื่อเปลี่ยนมาใช้ Round Robin และกำหนด Time Quantum เท่ากับ 3
P1 จะไม่ได้ใช้ CPU จนเสร็จในครั้งเดียว แต่ใช้ CPU ครั้งละ 3 units
แล้วเปิดโอกาสให้ P2 และ P3 ได้ทำงานด้วย

จากการทดลอง P2 สามารถทำงานเสร็จที่เวลา 5 และ P3 เสร็จที่เวลา 8
ส่วน P1 ค่อยทำงานต่อจนเสร็จที่เวลา 15 ทำให้ Average Waiting Time
ลดลงเหลือ 4.33 และ Average Turnaround Time ลดลงเหลือ 9.33

จากผลนี้ ฉันมองว่า Round Robin มีความยุติธรรมกับ Process มากกว่า
เพราะ Process ที่ใช้เวลานานไม่สามารถยึด CPU ไว้คนเดียวเป็นเวลานานได้


การประยุกต์ใช้กับ AI Inference API

จากการทดลอง ai_inference_scheduler.py มี User A ที่ต้องการสร้าง
10 tokens และ User B ที่ต้องการเพียง 2 tokens

เมื่อใช้ FCFS ระบบจะประมวลผล User A จนเสร็จก่อน หลังจากนั้น User B
จึงเริ่มทำงาน ทำให้คำขอสั้นต้องรอคำขอยาวที่เข้ามาก่อน

แต่เมื่อใช้ Round Robin ระบบจะสลับให้แต่ละ Request สร้าง Token
ทีละส่วน ทำให้ User B สามารถสร้างครบ 2 tokens และจบก่อน User A
แม้ว่า User A จะเข้าคิวก่อน

ฉันคิดว่าวิธีนี้เหมาะกับ AI Inference API ที่มีผู้ใช้พร้อมกันจำนวนมาก
เพราะแต่ละคนจะได้รับโอกาสในการประมวลผลโดยไม่ต้องรอให้ Request
ขนาดใหญ่ทำงานจนเสร็จก่อนทั้งหมด ทำให้ผู้ใช้ที่ส่งคำถามสั้นได้รับ
ผลลัพธ์ได้เร็วขึ้น และระบบให้ความรู้สึกตอบสนองเร็วกว่า FCFS


Time Quantum

ถ้ากำหนด Time Quantum ใหญ่มาก เช่น 100 Process ส่วนใหญ่จะสามารถ
ทำงานจนเสร็จภายใน Quantum เดียว ทำให้ Round Robin เริ่มมีพฤติกรรม
คล้ายกับ FCFS เพราะ Process แรกจะใช้ CPU เป็นเวลานานก่อนที่จะถึง
Process ถัดไป

ในทางกลับกัน ถ้ากำหนด Time Quantum เล็กมาก เช่น 0.0001 ระบบจะต้อง
สลับ Process บ่อยมาก ถึงแม้จะดูยุติธรรม แต่จะเสียเวลาไปกับ
Context Switching มากขึ้น ทำให้ CPU ใช้เวลาในการสลับงานแทนที่จะ
ใช้เวลาในการประมวลผลงานจริง

ดังนั้น Time Quantum ควรมีขนาดที่สมดุล คือไม่ใหญ่จนเกิดพฤติกรรม
คล้าย FCFS และไม่เล็กจนเกิด Context Switching overhead มากเกินไป


สรุปผล

จาก Lab นี้ ฉันเห็นว่าการเลือก CPU Scheduling Algorithm ส่งผลต่อ
เวลารอของแต่ละ Process โดยตรง FCFS เป็นวิธีที่เข้าใจง่าย แต่ถ้ามีงาน
ขนาดใหญ่อยู่ด้านหน้าจะทำให้งานขนาดเล็กรอนานจาก Convoy Effect

Round Robin ช่วยให้ Process แต่ละตัวได้รับ CPU เป็นช่วง ๆ ทำให้
ระบบมีความยุติธรรมและตอบสนองกับงานขนาดเล็กได้เร็วกว่า ซึ่งสามารถนำ
